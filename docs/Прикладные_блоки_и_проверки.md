## 2. Блок по лабораторным — что именно сверяется

### ЛР_01 · SE(3) и дерево координат ↔ tf2

| Понятие из работы | Контрагент в ROS 2 |
|---|---|
| класс `Transform` (R\|t) | `tf2::Transform`, `geometry_msgs/TransformStamped`, `pin.SE3` |
| словарь `PARENT` — дерево кадров | дерево `/tf`, `view_frames` рисует его в PDF |
| `lookup(a, b)` | `tf2_echo a b`, `buffer.lookup_transform(...)` |
| `world_from(f)` — накопление цепочки | `robot_state_publisher` из URDF |

**Проверки блока** (факт. вывод):
```
композиция цепочек: max ||pin.SE3 - Transform|| по всем кадрам = 2.49e-16
lookup(camera, object): расхождение = 2.91e-16
действие на точку: ||SE3.act(p) - apply_point(p)|| = 1.03e-16
```
**Как перепроверить**: открыть ноутбук, Restart & Run All → последняя ячейка
печатает `ПРИКЛАДНОЙ БЛОК: ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`.

### ЛР_02 · SO(3): exp/log, кватернионы, slerp

| Понятие из работы | Контрагент |
|---|---|
| `so3_exp` / `so3_log` | `pin.exp3` / `pin.log3` (основа MoveIt/Pinocchio) |
| `R_to_quat` (w,x,y,z) | `geometry_msgs/Quaternion` — порядок **x,y,z,w** |
| `slerp` | `Eigen::Quaternion::slerp` |

**Проверки блока**:
```
exp: max ||pin.exp3(w) - so3_exp(w)|| = 1.27e-15   (200 случайных w)
log: max ||pin.log3(R) - so3_log(R)|| = 4.71e-14
кватернион из матрицы: расхождение = 1.21e-16
slerp: max ||Eigen - наш|| в 19 точках = 7.28e-16
```

### ЛР_03 · Модель камеры ↔ CameraInfo и Gazebo

| Объект работы | Контрагент |
|---|---|
| `intrinsics()` → K | поле `.k` сообщения `sensor_msgs/CameraInfo` |
| `distort()` (k1,k2,p1,p2) | поле `.d`, `distortion_model: plumb_bob` |
| `project(K, R, t, X)` | конвейер `image_pipeline` |
| `Z = f·B/d` (задание 4) | `stereo_image_proc` → `depth_image_proc` |

Блок работает на чистом NumPy — внешних библиотек не требует вовсе.
**Проверки блока**:
```
CameraInfo.k -> K: расхождение с intrinsics() = 0.00e+00
f = 800 px, width = 1280 -> horizontal_fov = 1.3495 рад = 77.32 град
f·B/d: Z = 0.500 м — восстановление без потерь (задание 4)
```
Отдельный смысл проверки: Gazebo задаёт камеру через `horizontal_fov`,
связь с K — формула `f = width / (2·tan(fov/2))`; блок проверяет её туда-обратно.

### ЛР_04 · PnP и RANSAC ↔ cv2.solvePnP

| Понятие | Контрагент |
|---|---|
| `pnp_gauss_newton` | `cv2.solvePnP` внутри `ros2_aruco` |
| `ransac_homography`, порог 3 px | `cv2.findHomography(..., RANSAC, 3.0)` |
| `n_iters(eps, s, p)` | параметр `iterationsCount` ROS-нод |

**Проверки блока** (на живом OpenCV):
```
solvePnP vs ваш Гаусс-Ньютон: dw = 1.11e-16, dt = 1.11e-16
30% выбросов: ошибка позы с RANSAC = 0.0000 м, без RANSAC = 0.9132 м
inliers: 28 из 40 (подмешано 12 выбросов)
```
Ключевая демонстрация для защиты: один и тот же солвер с выбросами и без.

### ЛР_05 · DH-кинематика ↔ URDF

| Понятие | Контрагент |
|---|---|
| шаг `dh(a, 0, 0, θ)` | `<joint type="revolute">` с `<origin xyz="a 0 0"/>` |
| `fk_dh3` / `fk_poe` | KDL в `robot_state_publisher`, Pinocchio |
| облако рабочей зоны | planning scene в MoveIt |

Блок строит модель Pinocchio **из URDF-текста** (тот же файл лежит в
`docker/urdf/planar_3r.urdf`) и сверяет библиотечную FK с нашей.
**Проверки блока**:
```
модель из URDF собрана: nq = 3
50 случайных конфигураций: max || FK(URDF) - FK(PoE) || = 2.22e-16
```

### ЛР_06 · IK ↔ MoveIt и DLS-Ньютон

| Понятие | Контрагент |
|---|---|
| `ik2_newton` | IK-солверы MoveIt: KDL, Trac-IK |
| параметр `damp` | демпфированные наименьшие квадраты (DLS) |
| бассейны притяжения | «seeds» — начальные приближения солвера |
| ядро якобиана (задание 7) | нуль-пространство избыточных рук |

**Проверки блока**:
```
100 конфигураций: max || J_pin - jac2 || = 1.67e-16
та же цель [0.55, 0.30]: ваш Ньютон — 5 итераций,
библиотечный DLS (lambda=1e-2) — 5 итераций до 3.6e-13
3R: ядро J_pin == ядро J3 из задания 7, расхождение = 1.78e-16
```

## 3. Апофеоз ЛР_03–06 — сводный интерактивный стенд

Файл: `Апофеоз_ЛР03-06.ipynb`. Замыкает четыре лабы в контур
«увидел маркер → понял, где камера → решил, куда деть руку → двигает».

**Интерактив (ipywidgets)**: переключатель режима (ручной / цель-IK где
ползунки углов — семя солвера, видно бассейны притяжения), цель схвата,
доля выбросов, дисторсия в кадре, seed шума. Экран: 3D-сцена
(стол, маркер, рука 3R, оси камеры) + «кадр камеры» + числовой отчёт.

**Автотест конвейера** (последняя ячейка, факт. вывод):
```
FK:  max ||DH-цепочка - fk3|| на 100 конф. = 3.89e-16        (ЛР_05/06)
стерео: СКО при шуме 0.25 px = 0.0137 м, теория = 0.0138 м    (ЛР_03, з.5)
AR: при 30% выбросов dt = 0.0377 м, ложных inliers 0          (ЛР_04, з.5)
IK: невязка 3.02e-15, квадратичная фаза r₊₁/r² ~ [0.32 0.94] (ЛР_06, з.3)
граница: cond(J) при d=0.1 -> 7, при d=0.003 -> 41 (~d^-1/2)  (ЛР_06, з.5)
ядро: сдвиг вдоль ядра — схват сместился ≤ 2.4e-3 м           (ЛР_06, з.7)

АПОФЕОЗ ЛР_03-06: ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ
```
Методический нюанс, который виден в стенде и стоит проговорить на защите:
гомография из ЛР_04 даёт позу **от центра маркера**; сверять её надо с
`R₀·C + t₀`, а не с `t₀` напрямую.

## 4. Живые демонстрации в контейнере (docker/)

Не входят в ноутбуки — это отдельные сквозные демо ROS 2. Все проверены
end-to-end 14.11.2026 (три контейнера: state publisher, driver, viewer).

| Демо | Команда (в контейнере `ros2`) | Что увидите |
|---|---|---|
| Дерево /tf робота | `ros2 run robot_state_publisher ... -p robot_description:=...` + `js_publisher.py` | основа всех следующих демо |
| Живые числа lookup() | `ros2 run tf2_ros tf2_echo link_ee link_base` | аналог `lookup()` из ЛР_01 |
| Дерево одной картинкой | `ros2 run tf2_tools view_frames` | словарь `PARENT` в PDF |
| Качание шарниров | `python3 /labs/docker/js_publisher.py --sweep` | робот двигается синусоидой |
| 3D-анимация в браузере | `python3 /labs/docker/tf_viewer.py 15` → `open tf_animation.html` | записанное движение, вращение мышью (готовая запись: `docker/tf_animation.html`, 149 кадров) |

Нюанс Jazzy, важный для воспроизведения: `ros2 topic pub` на `/joint_states`
**не работает** — публикует пустую метку времени, и `robot_state_publisher`
молча отбрасывает такие сообщения. Поэтому драйвер — `js_publisher.py`,
который ставит живой stamp.

В образ `ros-labs-ros2` уже включены rviz2 и конфиг `rviz_config.rviz`
(RobotModel + TF + сетка); GUI на macOS требует XQuartz — HTML-анимация
даёт тот же результат без настройки экрана.

## 5. Как всё перепроверить самостоятельно

**Ноутбуки** (нужны numpy/scipy/sympy/matplotlib; блоки — pin, cv2):
```bash
cd ~/robotics/ros-labs-stand
jupyter lab    # открыть ЛР_0X_решение.ipynb → Restart & Run All
```
Или полный прогон всех шести из консоли:
```bash
for i in 01 02 03 04 05 06; do
  jupyter nbconvert --to notebook --execute --inplace "ЛР_$i/ЛР_${i}_решение.ipynb"
done
```

**Docker-демо**:
```bash
cd docker && docker compose build     # один раз
# далее по README.md из docker/: терминалы 1-2 (робот + драйвер), 3-4 (просмотр)
```

**Ожидаемый итог каждого прогона**: последняя ячейка блока печатает
`ПРИКЛАДНОЙ БЛОК: ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`, апофеоз —
`АПОФЕОЗ ЛР_03-06: ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ`. Любое отклонение — assert
упадёт с конкретным числом, а не «где-то ошибка».
